# Руководство по разработке WordFlow

## 1. Общие правила

WordFlow — командный проект для изучения английской лексики с помощью карточек.

Разработка ведётся с использованием GitHub Issues, отдельных веток и Pull Requests.

Все изменения должны быть связаны с соответствующей задачей (Issue).

## 2. Работа с ветками

Основная ветка проекта — `main`.

Для каждой задачи создаётся отдельная ветка.

Формат названия:

`feature/<issue-number>-<short-description>`

Примеры:

- `feature/1-init-vite`
- `feature/2-setup-vitest`
- `feature/3-git-workflow`

Новые независимые задачи следует начинать от актуальной ветки `main`.

Если задача зависит от изменений в ещё не объединённой ветке, допускается создание зависимой ветки.

## 3. Коммиты

Используем понятные сообщения в формате Conventional Commits.

Примеры:

- `feat: add vocabulary page`
- `fix: resolve flashcard validation issue`
- `test: add vocabulary unit tests`
- `docs: update contributing guide`
- `refactor: simplify flashcard state`

## 4. Pull Requests

Каждая задача должна завершаться созданием Pull Request.

В описании PR необходимо указать:

- Что было реализовано.
- Какие файлы или компоненты изменены.
- Как проверялась работоспособность.
- Номер связанной Issue.

PR должен быть направлен в соответствующую базовую ветку.

## 5. Code Review

Перед объединением изменений необходимо провести Code Review.

Участники команды проверяют:

- Соответствие реализации требованиям Issue.
- Корректность логики.
- Читаемость кода.
- Наличие необходимых тестов.
- Отсутствие очевидных ошибок.

Если обнаружены проблемы, автор PR вносит исправления.

После одобрения PR изменения могут быть объединены с целевой веткой.

## 6. Тестирование

Перед отправкой PR необходимо выполнить:

```bash
npm run test
npm run build
```

Обе команды должны завершаться успешно.

## 7. GitHub Project

Для управления задачами используется Kanban-доска.

Статусы:

- **Todo** — задача ожидает выполнения.
- **In Progress** — задача находится в разработке.
- **In review** — создан PR, ожидается проверка.
- **Done** — задача завершена.

## 8. Запрещённые действия

- Не выполнять прямой push в `main`.
- Не объединять PR без необходимого Code Review.
- Не включать изменения нескольких несвязанных задач в один PR.
- Не коммитить `node_modules`, `dist`, секреты и файлы `.env` с конфиденциальными данными.
